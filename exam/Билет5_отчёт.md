# Билет 5. Шлюз по умолчанию

## Схема

![Топология](../.github/assets/exam/01-topologiya.jpg)

Три компа (PC0, PC1, PC2) подключены к свитчу, свитч к роутеру, роутер к серверу.

| Устройство | IP | Шлюз |
|---|---|---|
| Router0 (в сторону компов) | 192.168.1.1 | - |
| Router0 (в сторону сервера) | 203.0.113.1 | - |
| Server0 | 203.0.113.10 | 203.0.113.1 |
| PC0, PC1, PC2 | по DHCP (192.168.1.10-12) | 192.168.1.1 |

## 1. Без шлюза

На PC0 поставил IP 192.168.1.10, шлюз не указывал.

- ping 192.168.1.1 - работает
- ping 203.0.113.10 - не работает (Request timed out)

Сервер в другой сети, а без шлюза комп не знает куда отправлять пакет.

## 3. ARP и MAC-таблица

`arp -a` на PC0 - там только MAC шлюза, MAC сервера нет, потому что комп всё отправляет через шлюз.

`show mac address-table` на свитче - видно какие MAC на каких портах.

![MAC-таблица свитча](../.github/assets/exam/09-switch-mac-table.jpg)

## 4. DHCP

Настроил DHCP на роутере:
```
ip dhcp excluded-address 192.168.1.1 192.168.1.9
ip dhcp pool LAN
 network 192.168.1.0 255.255.255.0
 default-router 192.168.1.1
 dns-server 203.0.113.10
```
Компы получили адреса автоматически.

Резервирование по MAC - это когда конкретному компу всегда выдаётся один и тот же адрес. В Packet Tracer на роутере это сделать не получилось, команды не работают.

![PC0 получил адрес](../.github/assets/exam/06-dhcp-pc0.jpg)

![Настройка DHCP](../.github/assets/exam/06b-dhcp-pool-config.jpg)

## 5. NAT

```
access-list 1 permit 192.168.1.0 0.0.0.255
ip nat inside source list 1 interface g0/1 overload
```
На g0/0 `ip nat inside`, на g0/1 `ip nat outside`.

Все компы выходят наружу под одним адресом 203.0.113.1. Проверял командой `show ip nat translations`.

## 6. DNS

На сервере добавил записи:

| Имя | Тип | Адрес |
|---|---|---|
| www.lab.local | A | 203.0.113.10 |
| www.lab.local | AAAA | 2001:DB8::10 |
| mail.lab.local | A | 203.0.113.10 |

- A - имя в IPv4
- AAAA - имя в IPv6
- MX - запись для почты. В Packet Tracer её нет.

Проверил через `nslookup www.lab.local` - работает.

## Почему ping работает, а HTTP нет

Сделал на роутере список доступа, который запрещает HTTP:
```
ip access-list extended BLOCK-HTTP
 deny tcp 192.168.1.0 0.0.0.255 host 203.0.113.10 eq 80
 permit ip any any
interface g0/0
 ip access-group BLOCK-HTTP in
```
Получилось: ping работает, HTTP не открывается, HTTPS открывается.

![ping работает](../.github/assets/exam/13-acl-ping-ok.jpg)

![HTTP не работает](../.github/assets/exam/14-acl-http-timeout.jpg)

![HTTPS работает](../.github/assets/exam/15-acl-https-ok.jpg)

![Счётчики ACL](../.github/assets/exam/16-acl-counters.jpg)

Ping и HTTP - это разные вещи. Ping проверяет только что связь есть. А HTTP может не работать, если:
- его заблокировали (как тут)
- на сервере выключен HTTP
- не работает DNS
